# Nexa 代理工作流

本文件补充 [AGENTS.md](../AGENTS.md)，只定义协作方式。动态任务、尝试记录和下一步写 [PROJECT_STATE.md](../PROJECT_STATE.md)，不持续扩充角色提示词。

## 1. 角色与路由

沿用项目现有角色设置，全部为 gpt-6-astra；实际宿主支持与用户指令优先。

| 角色 / effort | 职责 | 默认写入范围 |
| --- | --- | --- |
| 主代理 / max | 澄清目标、拆分、依赖、接口、整合、审查与验收 | 当前任务范围 |
| architect / max | 跨模块架构、数据所有权、兼容性与决策依据 | 只读 |
| coding / medium | 已确定接口的实现及相关验证 | 主代理明确分配文件 |
| debug / max | 复现、假设检验与根因 | 默认只读；获分配才修复 |
| search / low | 文件、定义、调用及引用定位 | 只读 |
| test / low | 指定检查、退出码与失败证据 | 不改实现 |
| worker / low | 简单、明确、局部任务 | 主代理明确分配文件 |

配置入口为 `.codex/config.toml` 与 `.codex/agents/*.toml`。它们控制开发代理，不构成 Nexa 产品的多 Agent 功能。需要更改角色配置时只改对应设置，不借工程任务扩大权限。

## 2. 协作约束

- 按任务需要启用，最多三个子代理；简单回复和一步操作由主代理完成。
- 主代理先冻结本次共享接口；同一文件只有一个写入者，有依赖的修改顺序执行。
- 子代理不再派生、不自行提交、不操作真实账号凭据；架构疑问及时返回。
- 只传最小上下文与相关入口，不让多个代理重复阅读全文或重复跑同一检查。
- 共用构建目录或依赖锁的操作由主代理协调；不能因“并行”相互覆盖产物。
- 实际验证失败时保留首个有用证据；两次有依据修复仍复现就转交根因分析。

## 3. 派发格式

```text
任务：任务 ID / 具体目标
已确认前提：设计决策与已完成依赖
允许范围：可读 / 可写文件，禁止改动
输入与接口：请求 / 事件 / 所有权 / 错误约定
交付：必须可审查的产物
验证：现有命令、模型/设备前置、期望判据
回报：结论、路径、退出码、风险、未验证项
```

没有实现的命令先交付命令入口或说明缺失，不把规格示例当成现有测试。纯文档任务不启动 runtime 或 Telegram 接入开发。

## 4. 回报与主代理验收

```text
结果：实现完成 / 待验证 / 受阻
变更：文件与主要行为
验证：实际命令、工作目录、退出码、证据路径
限制：未运行项、缺失条件、风险
下一步：依赖方需要的动作
```

主代理查看关键文件与证据，核对接口和生命周期；只有改动、失败或未消除风险才重复检查。终态由主代理整合后写入项目状态，子代理完成不能直接代表整个阶段完成。

## 5. 跨会话恢复

恢复时先读状态和索引，再核对实际文件。保护现有改动，不从零初始化已有模块，不把借来的项目历史或以前的推断当成验证。

本项目使用根目录 AGENTS.md 作为统一入口，不维护同内容的 AGENT.md 副本。宿主对指引发现的具体行为参考 [OpenAI Docs](https://learn.chatgpt.com/docs/agent-configuration/agents-md)；项目本身的工作规则以 AGENTS.md 为准。
