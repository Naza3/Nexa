# 查看与比较推理性能

启动新版 Nexa 及运行服务，正常使用聊天、图片 OCR，或通过 API 推理。请求结束后，点击左侧 **性能**；页面会每 3 秒刷新，也可点击 **刷新性能**。无需为聊天或 OCR 分别开启统计。

聊天回复和OCR识别结果的下方也会自动显示本次 **Prefill/Decode速度、耗时与token数**，无需切换页面；实际加载参数等明细可在“性能”页查看。摘要不混入复制的正文或保存的Markdown。指标查询失败只显示不可用，不影响已经生成的内容。

1. 按模型、状态、输入类型筛选记录。同一模型用同一张图片/同一段提示词比较。
2. 表格直接显示 **Prefill** 和 **Decode** 的 token/s 与秒数。
3. 点击 **查看 #编号**，查看实际上下文、线程、批次、输出上限、token 数，以及准备、输出回调、排队、加载、执行耗时。
4. 点击 **复制 CSV**，粘贴到表格软件保留本轮筛选结果。CSV 中阶段时间为微秒（`_us`），调度时间为毫秒（`_ms`），速度为 token/s。

记录覆盖聊天、OCR、本机和局域网 API 的流式/非流式推理，以及确实进行了生成的模型校验。服务只保留内存中最近 200 条已结束记录；重启清空。进行中的请求完成、取消或超时后才出现；在推理接收前就被拒绝的请求不计入。

| 观察 | 含义与比较方法 |
| --- | --- |
| Prefill 很慢 | 处理输入慢。图片包含图像编码，缩小图片或裁剪分块可能减少时间；同时比较输入 token 和实际耗时，不能只看 token/s |
| Decode 很慢 | 生成输出慢。固定模型、参数与输入比较线程设置；增加输出上限不会提高速度 |
| 准备很慢 | 模板、token 化、图片解码/预处理及预算检查耗时 |
| 加载很慢 | 模型冷加载耗时；与模型已驻留时的阶段测速分开比较 |
| 同步输出回调很慢 | 输出复制、锁或客户端消费等待的总开销；decode 已扣除这部分 |
| 失败／已取消／超时 | 保留状态、错误码和已知 token/调度时间，阶段速度显示不可用，不当作完整测速 |
| 成功 · 输出达上限 | 触及本次输出 token 上限；速度可比较，但内容可能尚未完整 |

Prefill 速度是输入 token 除以 prefill 时间；Decode 速度是原生输出 token 除以生成阶段时间。Decode 仍包含采样、文本处理及清理，不等于 llama-bench 的纯计算速度。缺测、零耗时不会补出一个速度。

同名模型可能被替换为不同文件。比较时请保持模型文件、设备、输入和实际参数一致，并将图片尺寸记在自己的实验备注中。性能页的200条内存历史不保存聊天正文、识别文字、图片或文件路径。

图片OCR另有最近100条结果归档，重启应用仍可查看识别原文和当时取得的性能摘要。它与性能页的200条内存历史不同；原图不保存，失败/取消及输出达上限仍保留不完整标记。
