# 错误诊断与显式恢复

本说明描述2026-10-09错误处理增量；不表示项目所有错误已穷尽或所有设备场景已验证。范围为启动、配置、模型/推理界面、下载清理与安装检查。验证与未验证条件见[联合记录](verification/2026-10-09-error-handling.md)，LAN公共行为见[ADR0042](decisions/0042-lan-bind-startup-recovery.md)。

## 共同原则

- 先保留真实错误类别和可确认的结果，再给明确的下一步。未确认状态不能显示完成，不把失败变成默认配置、自动切模型或自动重放请求。
- native/HTTP错误不是可信显示文本。桌面按有界code生成固定提示，仅保留严格匹配的安全原因、字段标签、数字OS/下载退出码和清理结果；未知错误降为通用提示。诊断复制同样不包含原始异常、路径、URL、令牌、提示词或生成正文，复制失败有可见反馈。
- 安全检查、身份/HMAC证明、配置CAS、锁、单actor、终态、任务取消/清理、部分输出保存继续保持。新文案不会扩大权限，也不自动清理用户文件或重新发起业务任务。

## 启动与私有诊断通道

桌面启动的`serve`显式设置`NEXA_DESKTOP_STARTUP_REPORT=1`，以stdout作为私有诊断管道、stderr保持null。只有该`serve`最终错误会写一行固定`nexa-startup-v1:<code>`；普通CLI命令、成功`serve`及公共HTTP/proof协议不变。错误写入失败（例如桌面退出关闭管道）不panic、不改变清理或返回值。

写端只格式化至256字节有界缓冲，再映射固定行，不发送原始错误。接收端单行最多256字节、解析最多64KiB，只接受完整固定码行，超过限额仍持续排空；进程退出后等待最多200ms，不让后代持有的管道阻塞窗口。私有stdout不替换worker的IPC；stderr保持原null继承，避免让保留运行的服务依赖桌面日志读端。此设计并不代替原生“关闭桌面且保留服务→外部客户端加载/推理→停服”验收。

固定启动码覆盖回环绑定、配置不可读/无效/繁忙、缺失worker、安全配置无效和通用启动失败。不可识别、超长或闭合不足的报告只生成通用错误，不以console全文作为兜底。桌面旧的`try_wait`异常交给既有reaper处理，不能遗留未管理child。

可选LAN的OS bind失败不走整体失败：保留已绑定认证回环，报告独立`lan_api.startup_error`且`running=false`。只有该OS失败可降级，配置和安全错误仍失败关闭。修正LAN配置必须显式停止服务，确认会中断所有客户端任务并卸载模型，然后保存、重启。

## 配置与模型/推理

配置错误的原主code、HTTP status、Display和字段标签保持；HTTP错误对象按需增加固定`reason`，不存在时省略。细分缺失、权限、路径安全、I/O、超限、UTF-8、TOML、schema和锁争用；客户端只接受与主code相容的reason，未知/不匹配原因忽略，不泄漏parser/OS原文。离线和在线bridge使用相同固定指引。

配置可能已发布但持久化未确认时保留草稿，先重新读取核对，不直接重复保存。服务启动/停止后的读回未确认，活动标记为待确认，不能宣称成功。模型未加载、模型冲突、队列满/超时、worker丢失等保留诊断类别，指导刷新/等待/显式加载；聊天与OCR失败保留已有正文，不自动重试或改用其他模型。

## 下载与文件结果

验证失败、验证后取消、发布失败必须显式收集临时文件清理结果；不能只依赖Drop却向用户声称清理成功。no-clobber发布后临时链接清理失败不撤销已提交文件。blocking任务异常退出可能发生在发布之后，标记`model_download_outcome_unknown`，先刷新目录/模型库核对，禁止据此自动重试或删除结果。既有有限下载恢复、固定来源、大小/SHA256和不覆盖目标约束保持。

## 安装检查

NSIS调用安装helper时增加`/diagnostic`，使用固定内部原因码区分不支持系统、用户路径查询/拼接、路径验证、进程状态验证和MSI查询。未知码仍通用失败；不能把“无法验证”说成已知进程运行或已知链接。提示为固定中英双语，不包含路径，失败仍关闭。

旧单参数helper返回值不变；内部20001–20005不作为NSIS对外退出码，对外仍1603/1638。MSI独立custom action、事务和回滚不变。不强杀程序，不删除模型/配置/凭据，不自动跨安装格式覆盖。详见[模板说明](../packaging/tauri/windows/README.md)。
