### 精确原因与最小修复

两份build-result只保留commit/hash，未含`source.diff_sha256`或脏文件清单。对精确registry源码`tauri-cli2.12.1/src/interface/rust/manifest.rs::rewrite_manifest`核对后，本地以同版本npm CLI、同build/target/locked参数和显式`--runner /usr/bin/false`执行规范化诊断，确切只改变`apps/desktop/src-tauri/Cargo.toml`两行：

- `tauri` inline table新增 `features = []`
- `tauri-build`版本字符串规范为 `{ version = "=2.7.1", features = [] }`

这是Tauri CLI在Cargo调用前的manifest规范化，`--locked`不禁止CLI写文件。把CLI自己生成的稳定形式作为源码后，第二次同CLI诊断的manifest、根Cargo.toml、根Cargo.lock字节hash全部不变；根锁没有改动。两个诊断runner都故意退出1，**仅证明规范化/幂等性，不是Windows编译验证**。日志、原manifest、前后hash和精确diff均保留在本轮证据目录。

修复同时新增一项manifest回归测试，并在实际Tauri构建完成后、旧native大编译前执行洁净源码断言：只记录相对`git status --porcelain`路径，不输出文件内容或完整环境。不增加ignore、不重置修改、不放宽下游T05/T06双clean-source门槛。修复后Linux Python45tests（2Windows-only skip）、壳5tests/clippy/fmt检查通过；仍须新源码的真实Windows CI复验。
