# Windows模型管理联合验收步骤

目标：Windows10 x64、i5-8400、16GB；Windows11独立记录。此清单是待执行步骤，不是通过报告。使用随后提供的同源完整测试包，不能仅替换EXE。

## 升级准备

1. 在旧Nexa明确停止服务并退出；确认没有仍在写入的下载/登记任务
2. 备份旧版本数据目录的 `config.toml`、`model-library.json` 和模型测试记录，不将密钥或完整私人路径上传
3. 新包解压到独立目录，保留旧包。第一次schema2登记/设置更新后，旧版未必能读取；降级需恢复匹配旧版配置/索引，后续新增登记会消失，原GGUF文件不会因此删除

## 浏览、添加与下载

1. 服务停止时打开模型页，确认已有登记列表可见，不必先启动服务，也不会自动扫描所有模型文件
2. “添加模型”选择一个位于其他文件夹的GGUF，确认无需复制，登记名称正确。再次添加同一文件不得重复增加相同记录
3. 多选不同目录模型，确认只登记选中文件，同目录未选择文件不会被偷偷加入；同名不同目录不得误当一个文件
4. 选择取消、开始校验后取消、关闭窗口再返回，观察操作终态；已发布成功不能同时显示“完全回滚”
5. 设置默认下载目录只改变位置；“手动扫描默认目录”是显式维护，不是默认启动任务。该动作不重新校验所有跨目录显式登记
6. 目录下载完成后应自动定向登记；若勾选可选加载测试，服务/模型忙时明确暂缓，不抢占当前任务

## 本机基础测试与状态

1. 加载一个模型，当前按钮显示“已加载”，模型行出现本次基础测试状态和完成时间
2. 再点基础测试，观察spinner/耗时，新完成时间更新；不能只读取旧Passed当作本次执行
3. 成功记录应显示基础生成通过；失败显示具体安全原因码，登记成功与测试失败分别表达
4. 卸载或切换后“已加载”状态跟随真实驻留；停止服务再打开模型页，历史本机结果仍能读取
5. 修改源文件/引擎/参数后的证据应过期，不应保留为当前组合已通过；不要为此改动唯一原模型，使用可恢复副本测试
6. 如仍异常，仅提供模型来源、界面安全原因码、是否首次或重复测试及报告，不需要密钥或生成私密正文

## 两个设置独立验收

1. 模型文件校验超时默认300秒，桌面范围30..7200秒；空闲卸载默认启用300秒，这是不同用途
2. 服务运行时不能保存运行策略。停止服务后分别保存两项，重开应用/服务应保留，保存一项不能覆盖另一项或LAN设置
3. 关闭自动卸载，启动服务并加载模型，超过先前空闲等待时间后仍驻留；显式卸载、切换模型、停止服务应正常释放
4. 重新启用自动卸载并设置较短合法等待，纯空闲时应卸载，正在生成或队列有任务时不能中途TTL卸载
5. 校验设置只改变文件准备预算，不是网络下载、native加载和短文本生成的共同超时；第三方API客户端有自己的等待限制

## 局域网（可选，单独记录）

按 `docs/lan-api-usage.md`，仅在可信私网手动启用。先核对实际IP/来源CIDR、独立LAN key和当前已加载模型。另一设备测试models及chat；未加载时不得远程暗中加载。不要关闭系统防火墙或配置公网端口转发。此包不自动修改防火墙，HTTP明文风险保持。

## 后期条件

无开发工具的干净机器、完全离线、长时间稳定性、Windows11及其他CPU尚需独立验证；本轮短验不代替这些条件。
