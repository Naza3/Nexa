# ADR0019：自动登记、离线模型库与本机基础验证

> 2026-10-04 用户后续选择以单文件/多文件添加为主，默认不再自动全量扫描。被动发现触发全库扫描的旧交互按 [ADR0021](0021-selected-file-model-registration.md) 替换；下载后定向登记与基础测试事实继续分开。

日期：2026-10-04。状态：实施与本地回归完成，新 Windows 包待构建/验收；本页不代表目标 Windows 已验收。

## 背景

用户已反馈当前版本可以下载模型，但下载后还需手动扫描、列表依赖运行服务、成功加载仍显示“未实测”，导致保存、登记和实际使用之间存在不必要操作。本决策覆盖 ADR0017 中保存后仅提示手动登记的旧交互，不改变 ADR0015 的开放候选与精确历史证据分离原则。

## 决策

1. **下载事实和后续步骤分开**：只有完整文件通过大小/SHA、受保护发布后才进入自动登记。复用原有 GGUF/模板/目录事务，不因来源是模型网站而跳过结构或完整性检查。保存已成功时，登记失败、短测试失败或晚到取消不将文件改称下载失败，不诱导重复下载。
2. **下载后可显式选择自动测试**：下载操作提供“下载后加载并进行基础测试（空闲时）”选项。只有此次操作明确启用才允许后续启动服务；旧调用未传选项按关闭处理。自动目标必须是本次文件对应的登记项，不能挑同目录第一个其他模型代替。
3. **浏览不启动服务**：本地已登记列表直接读取受限的持久化元数据，不调用会取独占锁、恢复事务或逐个完整 hash 的 `ModelStore::open`。真实运行信息与本地记录标明来源；通信或鉴权失败不伪称服务已停止。查看页面不生成凭据、不启动 API/worker、不加载模型。
4. **有界发现外部新增文件**：启动、进入模型页或刷新可做轻量稳定观察与去抖，只在变化后触发登记，不反复 hash 已有数 GB 文件。排除未完成下载后缀、同名 `.aria2` 控制文件和自有临时目录；真正登记仍进行完整结构/hash/前后身份检查。本片不是无界实时目录监听。
5. **保持运行中的存储所有权**：扫描登记仍遵守现有实例锁。服务运行时发现新文件先显示待安全登记，不暗中停服务或修改 actor 正持有的索引。在线原子更新索引是独立后续切片，不能删除锁检查冒充已经实现。
6. **自动操作有原子条件**：自动加载仅在 actor 未选择/未加载模型、无活动与排队请求时接纳；短测试仅对原子检查时相同模型及参数的空闲实例提交。条件不满足返回延期，不卸载别的模型、不插队、不回退为普通无条件 load/submit。用户显式切换模型沿用原显式加载语义。
7. **本机证据独立持久化**：不改历史 `validated`/`validation`，不把一次加载或生成授予全面兼容性、工具能力或质量标签。本机记录分别保存加载成功和基础生成通过，绑定模型/模板/文件身份、引擎构建、上下文/线程/batch 与平台/安装作用域；条件变化时标记失效，不能继续宣称当前配置通过。
8. **真实短测试**：加载成功后可发独立、有时间和输出预算的短生成，不污染聊天记录。必须观察真实非空输出、合理 usage 和成功终态才标通过；取消、超时、断流、空输出和失败不能通过。记录仅含受控状态、数字、摘要和错误码，不存聊天或测试正文。
9. **状态与生命周期真实**：界面分清保存、登记、加载和短测；本机“曾加载通过”不代表模型仍驻留。关闭/取消不得在用户认为结束后再新启自动任务，保存事实仍保留。没有后端支持的取消操作不能在 UI 假装完成。

## 非目标与兼容

- 不升级 llama.cpp、ABI、推理框架或包管理器；不恢复 其他平台/Harness 工作
- 不把固定下载目录变成模型许可名单，不按名字限制其他合法 GGUF
- 本机基础测试不证明长上下文、吞吐、长期稳定性、工具调用或回答质量
- API/DTO 的新增字段及条件入口应保留旧客户端普通调用语义；不对旧服务回退到不安全的无条件自动加载
- `acceptance-tools` 是使用固定模型的独立发行验收器，不是任意模型的基础测试实现，也不是已经完成的报告

## 验证要求

停止服务可浏览且无隐式进程/初始化；下载发布与登记失败分离；外部稳定文件发现、未完成文件排除、partial 登记与重复事件；actor 并发请求下原子延期且无暗中切换；证据失效与持久化；取消/关闭/失败不假报通过；旧历史矩阵仍不可伪造。逻辑/模拟、真实推理、Windows 文件保护、产品打包和目标机验收分层记录。
