# ADR 0001：Nexa 定位、命名与分层

日期：2026-09-30。
状态：历史总体设计基线；具体模块组织为设计决策，本文不代表功能已实现。2026-10-02起，Android引擎/模型资产及GPU/NPU路线以[ADR0008](0008-android-mnn-engine-and-package.md)为准，其余定位与调用层边界保留。

## 背景

目录原有一份 AI Runtime v0.1 执行规格，以及从其他项目借用的开发指引、索引、状态和开发代理配置。借用文件中的完成记录、提交、数据库版本和 Telegram 归档实现不属于本项目。

项目第一优先级为自己的 PC / Android 应用提供统一推理核心，首个业务是 Telegram 群消息摘要。当时以两端CPU为基础，尚无设备实测；当前平台/后端与公开参考设备见[架构](../architecture.md)和[状态](../../PROJECT_STATE.md)。

## 决策

1. 项目名统一为 Nexa。保留执行规格中的 ai-runtime、ai-runtime-worker、air_* 和 crate 名作为技术命名，避免仅改部分名称导致协议和脚本不一致。
2. 沿用 Rust + llama.cpp、自有 C ABI、PC 独立 worker 和移动嵌入线程。首版平台、CPU 基线、单模型队列、非思考文本子集与两端最小 UI 保持。
3. Telegram 消息来源与摘要任务属于调用层。以独立 summary-types/summary-core 和参考接入组织设计，runtime 不保存消息或检查点，不接入账号 SDK。
4. 摘要采用来源快照、token 分块、带证据要点和逐级合并的设计基线；质量与 runtime 功能分别验收。
5. 预算查询、模型能力和请求状态观察列为 S01 公共契约设计任务，尚未新增可调用路由。冻结时另建 ADR 并同步执行规格。
6. 任务路线保留 T00–T10，新增摘要 S00–S04；Android 风险探针尽早进行，完整 T07 仍受原依赖和真机门槛约束。
7. AGENTS.md 保存稳定规则，PROJECT_INDEX.md 区分实际入口与规划路径，PROJECT_STATE.md 只记现场事实、任务、证据与下一步。

## 未做出的决策

- 消息来源尚未选择：导出、已有应用、账号或机器人。
- 摘要触发方式尚未选择：手动、定时或持续更新。
- 手动单群文字摘要是首轮验证建议，不等于用户已接受。
- 未冻结默认模型、量化来源、上下文调整、质量/耗时门槛和业务持久化技术。
- 未决定加入 JSON/schema 约束、跨请求 KV 复用、GPU/NPU 或 Android 后台服务。
- 未授权自动向 Telegram 群发布摘要或其他外部消息。

## 影响与取舍

统一核心减少多个应用重复实现模型生命周期；两种宿主保留平台差异。参考摘要层增加可测试的真实业务入口，但不能成为 runtime 的必需依赖。

单模型和单运行槽简化首版生命周期；不同模型请求仍可能 model_conflict，多阶段任务需有限提交。Android 每个 App 有独立模型占用，当前前台规则限制无人值守摘要。

无跨请求 KV、受限上下文及无结构化输出都是明确的初始能力边界；通过真实业务实验决定后续扩展，不能隐藏在调用层里假定已经支持。

## 同步与验收

本决策同步到根目录三份入口文档、README、总体架构、摘要方案、路线以及原执行规格的项目定位与启动边界。

当前只有文档变更，不存在用户数据或已发布协议迁移。所有工程命令、版本锁和模型能力仍待相应任务落实；文档检查不能标记 T00 或 S00 已完成。
