# ADR0041：启动只校验声明的产品文件

日期：2026-10-09。状态：源码、本机测试与完整Windows交叉门槛已通过，原生运行待验证。

## 依据与决定

用户明确要求“不需要未声明文件的检验”。NSIS会在安装目录生成未列入产品payload清单的 `uninstall.exe`；启动不应因此拒绝整个安装。移除 `layout` 中额外文件/目录的全集枚举与拒绝，适用于桌面根及嵌套runtime/download布局；不是仅为卸载器增加白名单。

- 不扫描、打开、hash或识别未声明内容，任意名称、扩展名、空目录、嵌套目录和下载残留不再由启动库存校验拒绝；无关链接不遍历
- 三层manifest的产品/来源、边界大小、声明路径合法性与深度、大小/hash、SHA256SUMS精确对应仍检查；桌面、runtime、download各自的固定可执行文件必须显式列入清单，不能仅因普通文件存在就放行
- 声明文件及全部祖先仍拒绝symlink/reparse，保持普通文件与本地磁盘路径边界。忽略未声明内容不授予它执行、导入、删除或模型有效性资格
- pick/apply/rescan复用的包校验遵守同一规则；模型目录选择位置限制、实际模型扫描/导入/加载验证、ACL、token和数据配置不变
- 发行ZIP、构建产物、许可、PE依赖及下载组件执行前的独立身份校验仍保持原有严格规则；本次修改的是桌面启动/目录preflight，不把额外文件收入发行物

本决定替代ADR0007、ADR0017、ADR0018中启动阶段“仅指定位置GGUF/UUID残留可例外，其余未知内容拒绝”的部分；对应历史验证记录仍保留当时结论。

## 验证要求

回归覆盖 `uninstall.exe`、其他额外文件和目录允许，未知目录/链接不扫描；声明文件缺失、同大小篡改、清单/校验表不符及声明间接路径仍拒绝；自洽清单漏掉必需EXE仍拒绝。Windows安装生命周期在原版MSI/NSIS真实安装后运行已安装的 `nexa-desktop.exe --diagnose`，不以解压ZIP的诊断替代。诊断存入既有 `windows-desktop` 脱敏证据集合，安装门槛只在诊断与源码身份验证成功后成立。

`--diagnose`不初始化数据、不启动runtime、不建立WebView。它不能证明MSI另报的 `configuration_unavailable` 已修复，也不能替代用户Windows10实机启动/GUI验收。实际命令与限制见[本轮记录](../verification/2026-10-09-declared-payload-validation.md)。
