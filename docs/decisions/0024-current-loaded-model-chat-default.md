# ADR0024：空模型ID使用当前已加载模型

日期：2026-10-04。状态：源码实现与本地验证完成；用户已恢复GitHub Actions构建安排，尚未交付。

## 目的与请求语义

用户要求调用文本API时，空模型ID使用当前已加载模型。此为 Nexa 便利扩展，并非要求其他 OpenAI 兼容服务也接受空值；显式模型ID仍是跨服务兼容的推荐写法。

本机和LAN的 `POST /v1/chat/completions` 统一解释：

- 缺少 `model`、`"model": ""`、仅由空白组成的字符串：在本次准入时选择当前已加载模型
- `null`、数字、布尔值、数组和对象仍为400类型错误
- 非空字符串沿用严格 `ModelId` 校验，不按显示名称/文件名查找，不修剪合法ID周围的空格，不在ID错误时退回当前模型
- 重复字段、未知字段、消息与采样参数规则、鉴权、请求体/输出限制不变

## 原子性与生命周期

“当前”指调度actor处理此次命令时处于Ready或Generating的已加载模型。选择实际ID、检查状态与准入/入队必须在同一actor命令内完成，禁止HTTP层先读status再提交另一命令造成卸载/切换竞态。

无模型、Loading、Unloading、Unloaded或Faulted时，不猜第一个登记项，不触发文件准备/hash、隐式加载或故障恢复；按现有错误类别明确失败。运行中的同模型请求沿用原有限FIFO、输出信用、取消和deadline，不另建队列。停服、独占事务及容量限制仍优先按既有规则处理。

请求成功绑定之后，后续事件与响应都属于该实际模型。SSE每块与非流式响应的 `model` 必须是实际绑定ID，不能是空值、占位词或后来读取的另一个模型。进入worker/IPC的生成请求保持具体 `ModelId`，便利选择不扩散到推理内核。

## 显式ID保持原行为

- 本机：首次没有任何选择时可按显式已登记ID首次加载；同一selected模型卸载后可重载。已经选择其他ID时返回冲突，不自动切换。显式卸载保留selected_model，切换仍须本机加载管理操作
- LAN：仅接受已经本机加载的相同ID，无远程加载/切换/重载。空ID便利也不改变此限制
- `/v1/models`与模型登记ID/显示名称规则不变；本机列表是available登记候选，LAN最多返回Ready/Generating的当前模型

## 验证门槛

- DTO缺省、空串、全空白、null、各非法类型、非空非法ID、重复字段
- Ready/Generating成功；无模型、加载/卸载中、已卸载与故障状态失败且不调用resolver/加载
- actor选择绑定与卸载/切换顺序、队列/事务/停服边界
- 显式ID现有首次加载、同模型重载、错误ID与冲突回归
- 真实本机HTTP与LAN路由测试的SSE/非流式实际模型ID；模拟推理不冒充真实GGUF验收
- 本地源码回归与原生Windows/目标设备分开；用户已恢复构建授权，原生Windows Actions与新包结果须另行记录，不从Linux测试推导
