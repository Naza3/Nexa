# ADR0030：从模型库移除登记，保留模型文件

日期：2026-10-06。状态：开发与原生Windows验收通过，开发便携包已交付；目标Windows10窗口仍待用户验证。用户要求在模型库列表中增加移除功能；本决策不扩展为删除磁盘文件。

## 用户语义

- “从模型库移除”仅取消该模型的可见登记；外部 GGUF、下载文件、受控复制模型及其 manifest 均保留
- 操作前确认具体模型，并明确文件仍在磁盘；可以取消，不能用模糊“删除”文案暗示或执行文件删除
- 正常刷新、切页、程序或服务重启不会自动恢复已移除项。重新显式添加对应文件或适用的目录扫描成功后可以恢复登记
- 保留每模型设置、历史测试证明和聊天记录；重新登记后证明是否仍适用继续按原身份/参数规则判断，不转授旧测试成功

## 服务与事务边界

- 只允许从本机管理能力调用，不扩大局域网推理端点的管理权限
- 已加载目标必须先由用户显式卸载；生成、队列、加载、短测或其他互斥操作期间拒绝移除，不暗中取消请求、卸载模型或停止服务
- 服务运行时由调度器原子保留登记变更权限；服务停止时使用既有实例锁和登记操作互斥，避免与服务启动及其他添加/扫描竞争
- 请求携带列表代际，旧确认不能移除同 ID 的新登记；成功后发布新状态，失败不得先从界面永久隐藏
- 元数据有界、严格校验并原子落盘；提交前失败保留旧登记，提交后持久化不确定必须如实报告并重新读取实际状态
- `model-library.json` 新增 schema3，抑制登记及显式恢复与目录索引在同一文件事务中提交，避免分别写两个文件造成半提交。继续读取旧 schema1/2；只读浏览不重写迁移
- 外部登记原文保留，因此移除不释放既有64条外部索引容量；受控模型抑制最多1024条，全部索引仍受4MiB上限约束。达到上限明确报错，不淘汰旧抑制或自动扩大资源预算
- 取消登记不能调用现有破坏性的 managed-copy remove；不得为一次移除打开完整模型库并 hash 其他模型，也不修改 GGUF 或用户选择的模型目录
- 目录切换、同名不同文件、managed/external 身份与明确重新添加必须保持既有来源保护，不能只按展示名称删除或恢复

## 界面

复用模型列表紧凑操作和详情页，不增加常驻说明区。确认默认聚焦取消；移除中防重复提交，完成反馈短且可关闭。在用或过期状态显示可执行的解决方式，失败仍保留原列表。成功后清理被移除模型的当前选择、详情及暂存操作状态；较旧轮询不得把它重新加入列表，历史聊天不删除。

## 验证

覆盖受控复制与外部来源、文件字节保留、离线和在线列表、重启持久化、显式恢复、同名不同源、代际过期、重复点击、取消确认、加载/生成/排队竞争、原子保存失败与提交后不确定状态。前端模拟测试、Rust逻辑测试和原生 Windows 验收分别记录；不将 v0.1.0 已发布产物的证据作为此新增功能已完成的证明。

## 版本回退

首次明确登记变更写入 schema3 后，旧 v0.1.0 不保证读取新索引。不能通过删除抑制字段来伪装回退成功；这会让用户已移除的登记复活。模型文件始终保留，回退需使用相符的索引备份或由用户明确重新登记，不能自动删除模型或配置。此边界不影响现有已发布 v0.1.0 的文件与标签。
