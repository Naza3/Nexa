# ADR0023：模型文件校验超时与空闲卸载策略

日期：2026-10-04。状态：已实施并完成源码回归，目标Windows实机待验证。

用户选择显式添加模型、不再默认全量扫描，并要求区分文件扫描超时和空闲卸载。两者是独立行为，不应使用同一设置或以0隐式表示特殊值。

## 配置与兼容

`config.toml` 的 `[runtime]` 新增：

- `model_verification_timeout_seconds = 300`，合法范围30..7200秒
- `idle_unload_enabled = true`，缺省保持原有自动卸载
- 既有 `idle_unload_seconds = 300` 的桌面新保存继续限制1..86400秒；读取此前合法的手工长TTL配置仍兼容，不静默截断；关闭自动卸载不把秒数改为0

缺少新字段的旧配置按上述默认读取。新配置可能不被旧程序识别；升级前应备份原配置，降级时使用匹配版本配置，不能把这一兼容默认等同双向兼容。

## 文件校验

校验超时用于相应的文件内容/身份/metadata/hash准备及登记，每次操作开始读取配置后冻结，整次批处理共用预算，不是每个文件重新获得完整时间。只读模型列表不因增加设置触发扫描。

明确内容拒绝仍可列诊断；取消、超时、身份变化等硬失败在发布前保留旧索引。发布后观察到取消不能宣称已保存文件/记录回滚。下载传输、原生模型加载和短文本生成使用各自原有计时，本设置不延长这些阶段。同步系统I/O的调用边界仍取决于平台，不能承诺毫秒级强制打断任意文件系统调用。

客户端等待是另一个边界：仅在已证明的本机连接、且模型已登记为external来源时，对POST `/runtime/load`、`/runtime/load-and-test`、`/runtime/load-if-unloaded` 和 `/v1/chat/completions` 的响应头等待允许“本次校验预算+既有750秒”，最大7950秒。managed、状态、设置、停止和纯基础短测仍用原等待；取得SSE响应头后的流读取等待不变。这不延长原生加载/生成预算，也不修改服务端HTTP body读取或LAN连接限制。第三方API客户端仍需自行配置适当等待，不能保证其不会先取消。

## 不自动卸载

当 `idle_unload_enabled=false`，单actor跳过空闲TTL触发的卸载；显式卸载、模型切换、服务关停及异常清理仍有效。关闭自动卸载不允许第二个活动模型，不改变队列/取消/超时和worker生命周期，不允许LAN请求暗中加载模型。

保持模型驻留会持续占用对应内存；该功能不会防止Windows睡眠或进程被终止，也不是长期稳定性验证。已加载模型可以持续为本机和获授权LAN调用方待命，仍须遵守实际可用内存限制。

## 桌面保存

两个设置单独保存，避免页面旧值覆盖另一项。保留 `runtime_idle_save`，支持可选 `idle_unload_enabled`；省略时只改等待秒数，保留当前开关。新增 `runtime_verification_save` 仅保存校验超时。

所有运行策略保存必须显式停止服务，拒绝在运行或残留discovery无法确认安全时保存；取得实例锁后重新读取配置，仅修改本项，再原子持久化。前端显示单位、边界、保存结果和生效点，不能把已保存值显示成当前运行服务已经采用。新操作/下次服务启动读取更新值。

## 验证要求

覆盖旧配置、合法上下界及越界、关闭idle后时间推进不卸载、显式卸载/切换/关停、开启idle正常卸载、设置保存互不覆盖与锁/残留实例、每次deadline冻结/批次共用、取消前后保存事实、前端重复点击/关闭/晚回。最终与LAN、选中文件登记、本机测试证明一起回归；交叉编译与真实Windows设备结果分别记录。
