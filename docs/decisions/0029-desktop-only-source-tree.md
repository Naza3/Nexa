# ADR0029：安装器交付后仅保留桌面产品源码

日期：2026-10-05。状态：按用户明确要求实施；本批源码验证与后续原生构建分别记录，不把删除文件视为桌面回归通过。

## 前置与决定

用户要求先完成便携版、MSI 与 Setup 安装包，再移除 Nexa 项目内的移动代码和相关文档，后续专注桌面。精确 `de7732f` 的[原生构建](https://github.com/Naza3/Nexa/actions/runs/37306309927)、13项安装生命周期和独立产物复核已完成，三格式于2026-10-05 12:49:24 UTC交付；实际tag发布未执行。此前ADR0014的原位保留移动源码、隔离CI和未提交研究工作的限制由本次最新要求替代。

1. 从当前树删除 `apps/android-verifier/`、`mobile/`、`native/mnn-probe/`、`native/mnn-shim/`、`native/mnn-patches/`、`scripts/android_mnn/` 及两份Android MNN专用工作流，包含其专属研究许可材料；这些不属于桌面发行许可闭包。
2. 删除移动专用计划/契约、ADR0008–0013、三份移动验证报告及旧跨端文档快照。混合文档保留桌面设计和真实验证事实，移除移动专用段落、失效链接及当前保留要求；历史提交不重写，退役编号不复用。
3. 移除无桌面消费者的 `RuntimeConfig::android()` 与开发验收报告的 `android_arm64_cpu` 占位字段；零/一等待槽等通用调度回归改用明确测试配置，继续保留取消、deadline和有界队列覆盖。此报告字段不是HTTP公共协议或模型manifest。
4. Windows构建不再携带移动目录的忽略清单，源码边界检查只核项目自有工程。共享Rust服务、原生shim、IPC/API、GGUF完整性、manifest安全拒绝、安装/修复/升级/卸载和数据保留行为不因清理而放宽。
5. 独立 `Naza3/MNN` fork 不在本仓库改动范围。锁定 `vendor/llama.cpp` 上游Gitlink与完整源码保持，包含其跨平台代码、文档和许可；依赖锁里的上游平台包、完整许可原文和固定模型/模板/文本fixture也不为关键词清零而改写。

## 验收与边界

- 项目专用移动路径退出当前树；所有保留文档本地链接仍可解析，剩余平台词逐项区分当前非目标、历史边界、上游来源或固定fixture
- 当前桌面workspace、独立壳及相关逻辑/静态检查按实际结果记录；源码清理后的原生Windows与目标机结论需要新的精确来源证据
- 保留此前安装器交付的精确commit/hash与未验证条件，不能把它重命名为本次清理后的包
- 不创建tag、不发布Release、不合并main；提交/推送/CI由父任务依据现行授权统一处理

实际删除清单分类、命令与结果见[清理验证](../verification/2026-10-05-desktop-only-cleanup.md)，当前进度见[项目状态](../../PROJECT_STATE.md)。
