# ADR0022：Windows 数据目录与本机测试反馈修复

日期：2026-10-04。状态：已实施并完成源码回归，Windows实机待验证。

## 已定位的问题

用户反馈点击基础测试无明显变化、所有模型仍无本机证明，加载后按钮依然是“尝试加载”。代码核对发现：Windows 的 `ModelStore::open` 将私有数据目录规范化为 VerbatimDisk 路径，但库存/证明模块沿用用户外部模型目录的严格语法并拒绝该路径。错误被可选值转换或默认空记录掩盖，导致无法建立证明。此为代码级路径链定位，不冒称已经在目标 Windows 复现。

另有独立界面问题：按钮只依赖历史 `validated`；本次测试结果可能被刷新后的旧记录替代，重复通过也缺乏显著本次反馈。已有历史矩阵不能作为当前驻留或本机测试状态。

## 路径策略

- 保留 canonical PathBuf 原样，不通过移除 `\\?\`、截断、转小写或重新拼接路径改变文件对象
- 将受控内部数据目录与用户选择的外部目录区分；内部策略只额外允许本地 VerbatimDisk
- UNC、VerbatimUNC、设备命名空间、通用Verbatim/Volume/GLOBALROOT、相对与父级路径继续拒绝
- 盘符查询可以使用合法盘符的根；实际逐级打开、身份核验、读取和保存使用原路径，并保留祖先 no-reparse 与句柄保护
- 模型选择器、schema2显式外部来源、扫描和下载仍使用原外部路径策略，不借修复扩大网络/设备路径权限
- 库存、验证记录、桥只读模型页和实例观察中确属数据根的调用，使用专门的数据目录入口，不能只修服务端probe而漏掉读取链

## 证明与错误

本机证明仍绑定模型/模板hash、源文件身份、实际配对运行时/worker身份、安装/平台和加载参数。条件变化使其过期，不修改历史 `validated`，也不将加载成功当成生成成功。

真实未测试、证明不可读取、scope无法建立、保存失败必须区分。保留坏记录以便诊断，不静默覆盖或删除；错误使用安全阶段码，不含完整个人路径、密钥或生成正文。列表仍能显示模型，不因证明坏了就把模型藏掉或假报未测试。

只有观察到真实非空短文本、合理usage和成功终态才能认定基础生成通过；取消、超时、空输出或终态失败不通过。证明失败不能用旧Passed冒充本次成功。

## 界面

模型行显著显示本次操作的进行中状态、耗时、完成时间、通过/失败/暂缓/记录不可用及诊断码；不只依赖顶部通知或折叠信息。重复通过也能看到本次时间。当前驻留、登记/加载资格、本机历史证明、发布者历史矩阵分别表达。

已加载模型的按钮显示驻留状态，不再因历史矩阵缺项显示“尝试加载”；普通合法候选使用明确加载操作，错误时显示原因。晚到结果不得绑定到不同模型、文件、引擎或参数；关闭/取消不能触发新的后台测试。

## 验证分层

Linux用纯Windows路径分类表核对词法策略，不能用Linux Path组件冒充Windows解析。Windows gated最小用例以 `ModelStore::open(temp)` 的实际canonical目录读取空库存，再覆盖合成GGUF、普通/扩展路径同身份、证明写入/再次原子替换/重开与过期。

真实模型harness与Windows外部文件的加载→重复短测→停止→离线证明另做分层验证。交叉编译不等于Windows运行，合成证明不等于真实推理。前端测试覆盖忙碌、不接纳、重复通过、读写错误、刷新失败、旧证明、晚回与关闭。
