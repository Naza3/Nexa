# ADR0037：按导入顺序逐张OCR

2026-10-08，采纳。任务W02-OCR-6。用户要求一次处理多张图片，并明确默认按导入顺序，不按文件名排序。

## 桌面队列与单图引擎

批量编排归桌面调用层，复用既有 `ocr_start` / `chat_next` / `chat_cancel`。每个请求仍只有一张图片；本机HTTP单图预算、LAN文本边界、单actor/独立worker、IPC和原生计时不变。不增加并行推理、自动模型切换、PDF分页或拼接长图。

最多20张PNG/JPEG，每张最多4MiB、合计80MiB，原始尺寸限制仍是单边8192且不超过16Mi像素。按文件选择器返回的导入顺序显示序号，开始前可上移、下移、移除；不按名称、修改时间或EXIF重新排序，同名文件使用独立条目标识。超限整次拒绝并保留原队列，不静默只取前20张。文件选择器不保证鼠标点选时间顺序，以界面队列序号为准。

开始时冻结条目顺序、模型、提示词、输出token预算和发送图片尺寸。保留File引用，逐张读取/解码/缩放，不能同时预处理全部图片或给每张长期保留base64。当前预览之外，结果正文最多20×256KiB；超限停止并明确不完整，不静默裁切成成功输出。图片与待运行队列不落盘，不承诺重启继续任务；已保存的每图结果仍进入最近100条历史。

## 执行与恢复

每图有独立请求、状态、正文、usage、性能摘要和保存状态。只有收到与请求ID匹配、位于批次事件最后一项且terminal标志一致的可靠终态，才释放当前请求。成功（包括输出达上限并标记可能截断）且正文保存成功后才可进入下一张；性能查询旁路执行，迟到结果只能更新原图与原历史。

准备失败、提交失败、推理失败、用户取消和读取异常均暂停队列。停止先同步禁止后续调度，再取消当前请求；在准备、提交回执、读取和保存的异步返回之后均核对批次身份与停止/关闭状态。已运行条目不自动重放；用户明确继续时只处理未开始项，参数沿用该批次快照。

读取异常不等于终态，保持当前任务及队列占位；“重新确认识别任务”只读取/取消原请求，禁止重新提交。恢复确认后也不自动继续下一张。继续之前重新核对已加载模型和本窗口资源；其他API调用导致忙或模型变化时暂停，不自动换回模型。

## 窗口互斥与关闭

controller新增内存中的单owner批量占位，`acquireOcrBatch`同步检查并返回唯一token，`releaseOcrBatch`只接受匹配token，防止旧runner释放新批次。占位覆盖逐图准备、推理、正文保存与图间间隙；本窗口聊天、模型加载/卸载和其他冲突管理操作不能抢占。状态查询、历史保存、取消、终态消费和关窗收尾仍可执行；外部调用由既有actor准入裁定。

离开OCR页面不卸载队列，不重新提交当前图。正常关闭先禁止下一张、取消并消费当前图终态、保存已有部分正文，再复用ADR0036的设置/结果flush和原生关闭握手；无法确认终态或保存则保留窗口。未开始图片不创建空结果。

验证见[批量OCR记录](../verification/2026-10-08-sequential-ocr.md)。Windows文件选择器顺序、WebView2与用户i5-8400耗时仍需目标环境验证。
