# ADR0042：局域网绑定失败时保留本机管理

日期：2026-10-09。状态：源码实现，分层验证见对应验证记录；目标 Windows 设备体验仍待验。

## 背景与范围

用户遇到桌面 `runtime_start_failed`，直接运行 CLI 得到 LAN 端点绑定失败。旧行为在已成功绑定回环后，因可选 LAN 地址失效而丢弃全部监听，导致无法通过正常管理界面恢复。本决策只调整可选 LAN 的 OS socket bind 失败，不扩大远程暴露，也不把任意启动错误都转为可用。

## 决策

1. 持有同一实例锁，验证同一份配置快照后，依次尝试原配置的回环和可选 LAN 地址，各一次。LAN bind 失败时保留回环 socket，继续既有认证、HMAC 证明、发现发布、runtime 与关停流程。
2. `/runtime/status` 的 `lan_api` 保持 `enabled` / `listen` 表示启动配置、`running` 表示实际监听，新增可空 `startup_error`。失败时 `enabled=true`、`running=false`；桌面明确显示“局域网 API 启动失败，本机服务仍可用”，不得把配置启用等同 LAN 已启动，也不把模型状态标为 faulted。
3. `startup_error` 仅包含有界枚举：`address_unavailable`（网卡地址当前不可绑定）、`port_in_use`（端口占用）、`permission_denied`（系统拒绝，可能涉及保留端口/安全软件）、`bind_failed`（其他）。仅由 OS `ErrorKind` 分类，不透传原始错误全文、路径、凭据或请求内容，不把拒绝权限一律解释为防火墙问题。
4. 诊断属于当前进程启动快照，不持久化到 TOML。显式成功重启或关闭 LAN 后重启自然清除旧诊断；不自动重新 bind，不变更监听 IP/端口、不回退通配地址、不改 allowlist、鉴权、密钥或持久化 enabled。
5. LAN bind 失败不创建/轮换 LAN 密钥，已有密钥保持。LAN 成功绑定时仍必须成功建立原有独立凭据与安全上下文后才发布服务。配置校验、回环 bind、token/安全上下文、模型登记初始化、发现发布等失败仍按原流程失败关闭与清理。
6. 修正设置仍遵守停服和实例锁/CAS 门槛。顶层告警提供查看设置与显式停服入口；停服须复用确认框，明确会终止所有客户端任务并卸载模型，收到正常清理确认后才解锁设置。停服失败状态待确认，不自动重试、不偷停服务、不重放业务请求。
7. bridge 新字段采用反序列化默认值，兼容缺少字段的旧服务；前端旧字段缺失不臆造失败或运行，未知诊断文本仅给通用安全指引。公共 HTTP/proof 协议版本保持，新增字段不改变已有路由和成功状态字段含义。

## 不变边界与验证要求

LAN 仍是独立私有 IPv4 socket，只暴露文本推理路由，保留独立密钥、peer/Host/Origin/allowlist 校验、48/64 连接预算、模型本机加载和无明文安全承诺。不得修改防火墙/NAT，不能把本机降级恢复描述为远程可达。

需覆盖四类 bind 错误、禁用 LAN、配置无效、回环失败、原地址单次尝试、配置字节/凭据不变、真实 CLI 认证状态及停止/锁释放、显式重启清除、旧 DTO、UI 取消/确认/停止失败。主机测试、Windows 交叉编译、原生 CI 与目标设备实测分层记录，不能互相冒充。
