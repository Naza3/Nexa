# 局域网 API 使用与验收

当前实现与本地回归已完成，Windows局域网实测及联合包待验，实际可用版本以交付说明为准。这里只描述 [ADR0020](decisions/0020-opt-in-lan-inference-api.md) 的局域网文本接口，不代表目标 Windows 和手机已验收。

## 配置

1. 两台设备连接可信私有局域网，在 Windows 查询本机实际 IPv4。第一片只支持 `10.x.x.x`、`172.16–31.x.x`、`192.168.x.x`，不支持公网、IPv6 或 `0.0.0.0`
2. 在 Nexa 中显式停止服务后打开设置，启用“局域网 API”，阅读 HTTP 明文风险提示，填写该私有 IPv4 与端口（例如18081）
3. 填写允许客户端来源。优先指定单设备，例如 `192.168.1.30/32`；也可指定规范网段 `192.168.1.0/24`。只允许1–16条 `/24` 至 `/32`，不允许重复、重叠或空白名单
4. 保存后显式启动服务；确认实际 LAN 监听成功，再在本机加载要提供的模型。列表读取/保存不会暗中启动服务或生成密钥
5. 点击独立的“复制局域网密钥”，在客户端应用中粘贴；不要使用本机管理密钥，不要把密钥发到聊天、截图或日志

旧配置缺少LAN字段时默认关闭；写入新增配置后旧版本不保证识别，降级前应保留升级前的配置备份，不把密钥随包或报告分发。

原生复制使用系统剪贴板。启用系统剪贴板历史或跨设备同步时，应自行留意其保存/同步行为；Nexa不替用户修改这些系统设置。

## 客户端填写

- 类型：OpenAI 兼容文本接口
- Base URL：`http://<Windows私有IPv4>:<LAN端口>/v1`，例如 `http://192.168.1.20:18081/v1`
- API Key：从 Nexa 明确复制的局域网密钥
- Model：`GET /v1/models` 返回的当前已加载模型 ID，不是磁盘上的完整文件路径

支持 `GET /v1/models` 和 `POST /v1/chat/completions`，后者沿用现有严格文本 JSON 与 SSE/非流式行为。基础 chat 请求示例：

```json
{
  "model": "<models接口返回的id>",
  "messages": [{"role": "user", "content": "请用一句话介绍自己。"}],
  "max_tokens": 64,
  "stream": false
}
```

认证头为 `Authorization: Bearer <LAN密钥>`；JSON请求同时设置 `Content-Type: application/json`。密钥不能放URL查询参数。模型目录、模型加载/卸载、服务停止等管理操作不对局域网开放。

未加载模型时列表为空，chat不会替远端加载模型。空闲卸载后同样需要在Windows本机重新加载；需要长时间待命时可在本机设置关闭自动卸载：先停止服务、保存设置，再启动服务并加载模型。模型将保持驻留，直到显式卸载、切换或服务停止等事件；会持续占用内存。此功能不会阻止 Windows 睡眠。

## 连不上时

先确认服务实际运行、监听IP仍属于本机、客户端来源匹配名单、模型已加载、使用独立LAN密钥。设备换网络或DHCP换IP后，旧监听/白名单可能失效。

随后检查 Windows 防火墙是否允许该程序/端口接受指定来源的私有网络连接，以及路由器是否启用了访客隔离。Nexa不会自动修改防火墙或创建端口映射。不要关闭整个防火墙，不要为此开放公网或路由器转发。

浏览器网页的 Origin 请求默认拒绝，此片主要供原生应用和脚本客户端使用。能从Windows本机访问回环地址，不代表手机到LAN地址已通过；应分别记录。

## 必须保留的风险说明

本片是 HTTP，没有 TLS。Bearer认证和来源名单不能阻止同网段窃听；密钥与对话可能以明文传输。只在可信私有网络使用，不适用于公共Wi-Fi、互联网发布或不可信客户端。
