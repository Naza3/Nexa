# Windows CPU 单页 OCR 使用说明

本说明面向 Windows 10 x64、Intel Core i5-8400、16GB 内存，使用 CPU 运行 GLM-OCR。i5-8400 支持本项目 CPU 构建所需的 AVX2；此流程不需要 GPU。16GB 是整机内存，系统和其他程序也会占用，不能据此保证任意图片或上下文都能运行。

**需要包含 OCR 改动的新开发版。现有 v0.1.0 旧包不支持此功能。** 本文不提供尚未构建或发布的 Windows 包下载地址。拿到新包后应核对其源码身份和验证记录；仅版本号相同不能判断是否包含 OCR。当前交付状态以[项目状态](../PROJECT_STATE.md)为准。Windows 原生窗口和目标 i5-8400 设备的效果、耗时仍需实测，开发环境的 Linux CPU 结果不能换算成这台电脑的速度。

自行构建请从[项目 README](../README.md)、[构建锁](build-lock.md)和[桌面打包说明](../packaging/desktop-windows/README.md)进入，使用对应源码的现有构建与打包流程，不把新前端或单个 worker 混入旧包。桌面还需要 Microsoft WebView2 Evergreen。

## 导入并显式加载

两个文件可以放在“下载”文件夹，也可以放在不同文件夹；不用改名或放进 Nexa 安装目录。**放在同一文件夹不会自动配对，必须在下面两个选择窗口中分别选中文件。** 不用双击 GGUF，也不用执行普通模型目录扫描。

1. 打开包含 OCR 的 Nexa 开发版。首次使用点击“初始化并启动”；已有配置时点击“启动运行服务”。等左侧按钮变成“停止运行服务”，表示已连接，此时不要点停止。
2. 进入“图片 OCR”（快捷键 `Alt + 6`）。在“1 准备模型”区域展开“导入 OCR 模型与视觉投影”；没有 OCR 模型时此区域默认展开。
3. 点击“选择两个配套文件”。第一个窗口标题是“选择 OCR 主模型 GGUF（将复制两个文件）”：进入下载文件所在文件夹，选中 `GLM-OCR-Q8_0.gguf`，点击“打开”。
4. 接着出现第二个窗口，标题是“选择配套视觉投影 GGUF（mmproj）”：进入配套文件所在文件夹，选中 `mmproj-GLM-OCR-Q8_0.gguf`，点击“打开”。这是先后选择两次，每次一个文件，不是在第一个窗口同时多选两个。
5. 回到 Nexa 后，应在选择按钮附近看到“两个文件已选好”以及主模型和视觉投影的文件名。若取消或失败，同一区域会显示原因及错误码；还未选好两个文件时不会开始导入。
6. 在出现的“模型 ID”输入框填写 `glm-ocr-q8`，点击“复制并导入两个文件”。等待“正在复制并校验”结束，看到“双文件导入完成”。程序会保存一份受管理的配对副本，源文件保留；不必自己寻找托管目录。不要通过普通“添加模型”代替这一步。
7. 导入成功后“OCR 模型”列表会刷新。手动选择新条目，检查下表三个参数，然后点击“加载所选 OCR 模型”。等顶部显示“OCR 模型已就绪”后，再到“2 选择图片”区域选图。

导入不会自动加载，开始识别也不会偷偷更换模型。下次使用已导入模型时，不用重复选择两个 GGUF：启动服务后直接选择并加载即可。

若旧包选完主模型后没有第二个窗口，可能命中已确认的 Windows 路径转换错误；含[配对修复](verification/2026-10-07-ocr-pair-and-layout.md)的新包才具备本轮修正，移动文件夹或重复点击不能修复旧程序代码。新包的原生执行与用户目标机结果以验证记录为准。

| 本次加载参数 | 初始建议 | 使用方式 |
| --- | ---: | --- |
| 上下文 | 8192 | 为图片、提示词和输出共同留出空间，仍须符合模型上限 |
| 批次 | 256 | 首次按此值验证，再按实际资源情况调整 |
| 线程 | 4 | i5-8400 可对比 6；线程更多不保证更快 |

这些输入框可编辑，并作为本次显式加载的临时覆盖值，不改写已保存的模型档案。页面显示当前实际加载上下文；修改输入框后必须再次显式加载才生效。不要沿用 2048 上下文同时要求 2048 输出：图片和提示词还需要额外预算。

Nexa 保持单模型、单运行任务。已有聊天、OCR 或其他客户端任务时先等待或停止自己的任务；不要为了换模型误停其他应用。视觉模型加载成功只证明本次可加载，会跳过纯文本基础测试，不能称 OCR 已通过。

## 调整推理执行超时

如果识别在执行超时后停止，可在包含本轮修复的新包中调整统一设置。打开“设置”，找到“推理执行超时”，按需要填入 `1800` 秒（30分钟）；默认300秒，允许1–86400秒。此设置同时影响文本聊天和图片OCR，覆盖图片处理、提示词准备与生成，不保证延长后一定完成。

先等待当前任务结束或停止自己的任务，再点击“停止运行服务”；确认已停止后保存设置。随后重新启动运行服务，回到“图片 OCR”，重新选择并显式加载所需模型，再手动发起识别。保存值只有重启后才成为当前服务的执行预算；失败或取消的请求不会自动重试。

旧包需要整套升级到包含此修复的桌面与runtime配套产物，单独修改配置或替换前端不能修复旧桌面的固定等待上限。新包会按当前服务的有效配置调整等待时间，不需要再设置单独的桌面或OCR超时。实际可用发行包及Windows验证状态仍以[项目状态](../PROJECT_STATE.md)为准。

## 选择图片并识别

- 只接收一张 PNG 或 JPEG，文件最多 4 MiB；单边最多 8192 像素，总像素最多 16,777,216。损坏图片会拒绝。文件大小和原始尺寸限制在缩放前检查，超限图片请先在外部图片工具中裁剪或缩小。
- 点击“2 选择图片”区域的“选择图片”按钮，在窗口中选中图片并点击“打开”，然后查看预览旁的文件名和准备状态。准备成功会显示图片；失败会在这里说明原因，可重新选择同一文件或其他图片。程序按图片内容识别格式，系统未正确标记 PNG/JPEG 类型也可读取；仅修改扩展名不能把其他格式变成受支持的图片。
- “发送图片尺寸”默认“原图（不缩放）”，也可主动选择最长边 1600 或 2048。缩放保持比例，不放大小图；缩放后的图片也须符合大小限制。界面预览的是本次发送的图片。
- 原图更利于保留小字，但可能增加处理成本；1600/2048 可减小输入，却可能丢失细节。先用清晰的小裁图验证，再尝试整页；去掉大面积空白，保证文字方向正确，按需要将密集页面裁成几块分别识别。
- 识别提示词默认 `Text Recognition:`，可手动修改。最大输出 token 默认 2048，可设为 1–4096。图片 token、提示词、模板与输出共同占用上下文；后端会精确检查预算，超限会报错，不自动截断或重新加载。降低输出上限可能截短正文，应结合页面长度选择。

模型加载完成、图片预览出现后点击“识别图片”。页面流式显示生成文字；本次请求仅包含当前图片与提示词，不附带聊天历史。逐页核对数字、标点、表格和小字，不能把“识别完成”视为内容无误的保证。

页面按“准备模型 → 选择图片 → 识别结果”排列，沿用 Nexa 的现有卡片、字体和按钮风格。宽窗口中图片与结果并排，窄窗口中上下排列；“3 识别结果”区域保留独立滚动，方便查看长文本。

可切换“原文”与“Markdown”查看；Markdown 只是安全排版，不改变原文。“复制识别原文”复制原始文本；“保存 .md”打开原生保存对话框，由你选择文件位置。停止或失败后已有部分文字仍保留，可以复制保存，但必须按不完整结果处理。达到输出 token 上限时会明确提示内容可能截断，也应核对原图。

## 停止、恢复和资源选择

点击“停止识别”后等待停止确认。切换到其他页面不会另开 OCR 请求，返回“图片 OCR”仍可停止原任务；关闭窗口会走本窗口任务的取消与清理流程。取消、断流和失败均不自动重试。读取或停止确认异常时，点击“重新确认识别任务”继续确认原请求；终态消费完成前保持任务占用。若读取曾中断，即使后来确认完成，已显示原文也可能缺少部分内容；达到输出 token 上限时同样按可能截断处理。若界面提示结果与停止尚未确认，使用“重新确认识别任务”读取原任务的最终状态；在收到终态前不能开始新的识别。该按钮不重新生成内容。

若服务显示 `Faulted`（故障），先查看错误及活动信息，再显式重新加载模型恢复；不要持续点击识别或把部分输出当成完整结果。加载或停止未确认时先等待清理、查看诊断。图片坏损、预算超限等输入错误应先修正输入，不必把每种报错都解释成进程故障。

连续处理多张图片时，可在已保存的空闲策略允许范围内保持模型驻留，减少重复加载。结束后按需要卸载模型以释放内存。SSD 主要有利于文件读取和模型加载，不能据此保证识别生成更快。i5-8400 上应使用相同图片、输出上限及上下文分别比较 4/6 线程，记录实际表现；本文没有该设备的速度承诺。

## 能力范围

这是 Nexa 的单页图片 OCR 入口，使用官方 GGUF 配对资产和锁定的推理核心。它不包含官方完整文档处理流程中的版面检测、多区域编排或 PDF 流水线；没有批量多页 PDF 导入。需要识别 PDF 时先用自己的工具导出符合限制的单页图片，并逐页核对结果。当前局域网 API 仍为文本服务，不承接这条图像请求链路。

## 对比识别性能

请求结束后打开左侧 **性能**，输入类型选 **图片**，查看prefill/decode速度、耗时和本次实际上下文/线程/批次；可复制CSV对比不同图片尺寸。prefill包含视觉编码，失败/超时不显示成功测速。聊天及API也使用同一系统，步骤见 [统一性能使用说明](inference-performance.md)。
