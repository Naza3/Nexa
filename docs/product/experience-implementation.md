# Nexa 整体体验实施契约

状态：用户2026-10-04已批准实施。起点为 `6aa0e1f`，在长期 `codex/dev` 顺序推进；设计稿是目标，不是已完成能力。精确完成/验证以当前状态与后续记录为准。

## 产品主线

Nexa是Windows桌面CPU本地模型服务管理器，主要结果是其他本机或可信局域网应用可以使用已配置的模型。主流程为准备模型文件、登记、明确运行档案、启动服务并加载、接入客户端、观察与恢复。聊天为辅助测试，不扩展为独立会话产品。

一级导航为概览、模型库、API接入、活动；设置为低频入口。侧栏服务主控保留。主要信息与操作由同一状态投影派生，不由各页自行决定“成功”“加载”“运行”的含义。

## 状态与任务

- 区分文件/登记、服务、实际驻留、上次选择、请求和后台任务；selected_model不是驻留证明
- 服务状态未知或清理未确认不冒充已停止；卸载中不冒充内存已释放
- API监听成功不等于模型可用；空model和LAN要求Ready/Generating，本机显式同selected恢复仍沿实际会话参数
- 已确认的任务归全局所有，不因导航丢结果或取消后续阶段；重复点击不重复执行，旧回包不得覆盖新操作
- 活动记录本地有界且可清理，不保存默认请求正文、生成正文、密钥或不必要路径；重开对账，不自动重放旧推理或破坏动作
- 仅提供后端真实支持的取消；等待取消确认。加载/原生初始化等无独立取消能力时明确提示，不假取消或为此误停其他客户端
- 停止服务保留取消所有客户端任务并等待清理的语义；忙时说明影响。繁忙模型切换/重载拒绝，不抢占其他客户端

## 设置与模型档案

明确加载的参数优先级为本次显式覆盖、模型档案覆盖、全局运行默认。档案以稳定ModelId索引，UI和API通过同一解析器获得有效值，不按文件名或展示名映射。

加载参数保存不意味着改变当前worker。临时覆盖标为本次服务会话；空闲卸载后的同selected自动恢复继续原会话快照。主动加载/重载、切换或服务冷启动按最新档案解析。界面显示已保存值、覆盖来源、未保存草稿与实际驻留参数；未驻留不显示虚假生效值。

旧桌面和API配置相同可合并；不同必须显示差异由用户确认，未确认不改变原API行为。写入必须在共享写锁内重读、比较revision、校验并原子发布；CAS冲突零写入。保留原ID、模型、密钥、旧配置备份与迁移凭据，不用跨两文件写入冒充原子事务。

首次初始化与服务启动分开；读设置、编辑草稿不隐式启动服务/扫描模型/创建LAN凭据。监听、idle与其他需要重启的进程策略仍停服保存并明确生效时间。

## 模型与API工作区

- 添加文件为默认入口；扫描只在高级维护，刷新不全库hash
- 外部导入原地引用；目录更改不搬已有文件。下载、校验、登记、可选加载和短测分阶段，保留部分成功事实
- 获取模型默认不抢占正在服务的模型；单项可明确选择加载并测试，批量不自动串行切换
- 现有下载/登记停服锁保留，必要停服明确征得用户在应用中的确认；不承诺当前已有在线获取/登记
- 历史验证精确绑定条件但不是加载白名单；正常列表简洁，详情保留全部证据与代码。已知超限与泛化原生失败分开，未知错误不诊断为OOM
- API接入区统一提供含 `/v1` 的Base URL、实际模型ID、鉴权状态、有效监听与复制入口；密钥继续原生安全复制，不进入JS
- LAN仍默认关闭、具体私有IPv4、独立凭据和来源CIDR；不放宽Host/Origin、回环管理、单驻留和队列边界，不自动改防火墙
- 关闭窗口保留服务、停止服务并退出分别命名；保持/空闲释放策略后果清楚，当前无托盘不得假称有托盘
