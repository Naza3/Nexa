# Nexa 简洁桌面体验契约

状态：2026-10-05 设计、前端实施与源码流程模拟完成，654项前端测试及独立审查通过；不代表原生窗口、Windows 鼠标/键盘或最终版本验收完成。

本轮输入：用户明确要求“简洁优雅而又符合人机工程学”，允许整体重新设计，而非只修改模型页。此前已确认：一级界面少字，详情进入二级；模型真实测试成功使用绿色背景，失败使用红色背景，其他测试状态不着色；目录与下载维护归设置；状态栏位于整个应用底部。

本文细化[整体体验实施契约](experience-implementation.md)的页面层级与交互，不另造运行状态，不改变 [ADR0025](../decisions/0025-unified-model-profiles-and-configuration.md) 的配置/档案语义。用户最新要求优先；后端和安全边界继续遵循 [AGENTS](../../AGENTS.md)。

## 1. 设计目标与不变项

让用户在不阅读说明书的情况下回答三个问题：

1. 现在服务是否可调用，真正驻留的是哪个模型？
2. 此页最相关的下一步是什么，点击会影响谁？
3. 操作没完成时，去哪里看真实结果、取消或恢复？

简洁来自减少同屏决策与重复，不是缩小文字、压低对比度或隐藏错误。默认页只显示决策所必需的信息；次要信息在有名字、有返回路径的二级区域。不能将模型页删除的说明全部堆到概览。

保持以下语义：

- Windows CPU 模型/服务管理器；聊天为辅助验证，不能占据主工作区中心
- 只允许一个驻留模型和一个执行任务；切换不得抢占其他客户端
- 选中、登记、曾加载、真实驻留、测试通过相互独立
- API 密钥由原生端复制，不进入 JS、日志、DOM 或持久化草稿
- 目录保存不搬动文件；下载/登记仍遵守现有停服限制
- 配置使用 CAS；草稿、已保存、当前实际生效、下次加载生效分开
- 取消等待真实终态；断连不假定成功或回滚；已有输出不自动重放
- 不增加模型删除、托盘、自启、GPU、模型市场或其他后端能力

## 2. 统一窗口结构

### 2.1 稳定导航与视觉重心

左侧固定短导航：概览、模型库、API 接入、活动；设置置于下方。每项保留图标和中文名称，去掉重复副标题、“工作空间”分组说明和宣传卡。聊天测试从驻留模型或 API 的次级动作进入；进入后明确返回来源。

保留唯一的全局服务主控，放在侧栏低部并使用完整动词：启动运行服务、停止运行服务、重新检查服务。不能把它缩成无标签电源图标，也不能同时在多个页面放外观相同但后果不同的主按钮。停止操作继续说明会中断其他客户端。

应用底部始终保留独立状态栏，不归属于某页正文：

- 左：服务状态；中：真实模型状态/驻留名称；右：在途任务摘要及活动入口
- 默认约 36–40 px 高，窄窗口可用两行；正文必须为其预留空间
- “正在加载”“停止中”“状态待确认”都有文字，不依赖圆点颜色
- 加载参数、内存观测、历史选择、诊断码不全部塞入状态栏
- 上方如保留面包屑，只承担位置，不再重复服务状态

错误、待恢复配置和必要确认属于上下文内容；状态栏不能代替它们。

### 2.2 尺寸、密度与样式建议

沿用当前紫色强调色和 Segoe UI / Microsoft YaHei UI 字体族，不另造视觉语言。以原生默认窗口 1120×780、最小窗口 760×580 为设计基准，以下为目标而非已测尺寸：

- 侧栏约 172–184 px；内容左右留白 24–28 px；小宽度缩至 16 px
- 页面标题 24–26 px；章节标题 16 px；模型名/正文 14 px；次要说明 12–13 px
- 一级交互的解释不使用 11 px 小字；默认行高 1.45–1.6
- 采用 4/8 px 间距阶梯：同组 8，组内 12–16，组间 24；少量 1 px 边界取代每层大卡片
- 普通按钮至少约 36 px 高；图标按钮至少 32×32 px 且有可访问名称
- 模型行以约 72–88 px 为目标，长名称允许换行；不能用固定高度截断错误或焦点框
- 主要操作只用一个强调色按钮；次要操作中性，危险动作只在必要确认处突出
- 名称、路径和 ID 容器使用 min-width: 0 与适当换行，按钮不被挤出窗口

建议使用窗口级 grid/flex，正文 min-height: 0 并独立滚动；侧栏和底部栏保持可达。避免正文、卡片、详情同时形成三重滚动。弹窗超长时只滚动内容，按钮可达；小窗口与系统缩放必须另做原生验收。

## 3. 页面层级

### 3.1 概览：现在是什么状态，下一步做什么

保留一个当前运行主区和一个最近/当前任务区，不再重复服务卡、驻留卡、接入卡中的同一事实。

- 首次启动：一句“添加一个模型开始”，提供添加文件与下载入口；离线初始化仍可由设置明确完成，不因打开页面自动启动
- 已有模型、无驻留：显示“无驻留模型”，主动作“选择模型”；上次选择仅以次级历史标记显示
- 模型就绪：名称、就绪状态、一行实际上下文/线程；主动作“API 接入”，次级“模型详情”“聊天测试”
- 生成中：显示真实工作状态；不许把本窗口没有任务写成全服务空闲
- 运行故障/未知：错误原因与对应恢复入口优先，不能出现绿色“可调用”状态
- 在途任务有摘要与查看入口；无任务时一行说明即可

空闲策略移至展开的运行详情或设置。没有原生剩余时间就不显示倒计时，也不以“未报告”的重复段落占据首屏。

### 3.2 模型库：先找到和使用，再查看详细信息

首层结构：标题与添加按钮 → 本地/下载短切换 → 紧凑模型列表。不要在列表前放大型运行、目录或维护卡片。

本地行必需信息：模型名称、量化、大小、简短真实测试状态、驻留标记和一个主要动作。加载成功与测试成功使用不同文案。源文件不可用等直接阻断操作的原因保留一行，不藏到详情。

操作名称由实际状态决定：

- 无驻留：加载模型；点击可能启动服务并短测，此后果在操作附近或首次确认中清楚说明
- 当前驻留：已加载标记；基础测试为显式动作，不能再给一个看似可重复加载的主按钮
- 其他驻留模型：切换并测试；确认点名新旧模型并说明失败不自动恢复旧模型
- 繁忙：动作禁用，附近简短说明等待当前任务，不使用只有 hover 才可见的原因
- 文件不可用：当前不可用，并显示具体、受控的原因

二级详情包含：

1. 文件与身份：API ID 及复制、架构、存储来源、hash、上下文约束
2. 运行档案：继承来源、已保存解析值、实际驻留参数、会话恢复参数、草稿与应用动作
3. 测试与诊断：本次结果、时间、历史记录、精确证据范围、诊断码

详情应为可返回的页面/面板，或一个默认收起、具有语义标题的 details。禁止让“查看详情”文字可点击却无法用键盘操作；也不要把整个含按钮的行再嵌入另一个 button。

返回列表要保留本地/下载视图、当前页与原模型位置。仅浏览不能触发扫描、重新哈希或加载。模型不在当前页时，不把旧详情对应数据冒充当前列表新行；应明确保留已打开身份或提示需重新读取。

### 3.3 模型测试状态与色彩

颜色只由受控的本机测试结果派生，不能使用 selected_model、runtime ready、文件登记或历史 validated 布尔代替：

- 当前有效、真实短文本测试通过：绿色背景与“基础测试通过”
- 真实失败：红色背景与“测试失败”或准确的失败文案
- 未测试、仅加载成功、正在加载/测试、延期、取消、记录过期、结果未确认：中性背景，配清楚文字
- 原先通过但本次仍在途：本次状态优先，不让旧绿色掩盖新尝试
- 记录读写失败：明确“记录未确认”，不能继承此前通过；具体是否为执行失败须依错误事实区分
- 架构/文件不可用错误与测试状态是两项事实，不统一涂成“测试失败”

测试颜色可作用于紧凑状态标签或结果区，不能将整个页面变成状态色。绿色/红色同时配文本与图标；过期证据必须降为中性。

### 3.4 下载与添加：任务流程，非说明书

下载首层只保留筛选、当前来源/目标摘要、模型名/量化/大小/简短建议、下载动作。许可、固定版本/hash、下载来源完整身份、内存边界进入详情，但选择会影响是否可用的缺失来源/目录、服务未停止仍显式可见。

“下载后加载并测试”默认关闭，靠近下载流程，明确它会启动服务且忙时暂缓。不能将下载文件完成显示成模型已通过测试。

文件选择后显示选择数量、文件名/大小、零复制说明与一个确认添加按钮；批量不支持自动轮换测试。选择只是未提交草稿；导航不提交，也不伪称已登记。显式停服后保留文件选择，仍需点击确认添加。

从下载去设置修复目录/源，再返回时保持下载视图及筛选。设置应有明确“返回下载”或保留原导航上下文，不能让用户再次寻找入口。来源只在显式保存后变化；在途任务继续显示其真实来源和目标。

### 3.5 API 接入：三项连接信息

默认显示本机连接信息三行：Base URL（含 /v1）、真实驻留模型 ID、原生安全复制密钥。每行紧邻对应复制动作，成功反馈点明复制了哪项，不能用笼统“操作成功”。

无驻留时 ID 显示“请先加载模型”，不使用上次选择顶替；Base URL 可以复制不等于服务已可调用，连接状态要独立展示。密钥复制保留原生路径与剪贴板风险确认。

二级分组：

- 连接说明：空/缺省 model 绑定当时驻留、显式 ID 不隐式切换、文本能力边界
- 本机监听配置：保存值与有效监听、停服要求、端口编辑
- 局域网接入：默认关闭；展开后显示私网地址、允许来源、独立令牌与有效监听

本机/LAN 的编辑只保留一个归属入口，不能在设置再复制一套表单。LAN 的关闭不能掩盖保存与当前运行不一致；未保存、运行未采用、验证失败必须在分组摘要中可见。

### 3.6 设置：按任务分类，遵守原保存边界

建议使用纵向可折叠分组或短分类切换：

- 模型与下载：默认目录、目录状态、显式维护/扫描
- 界面与下载偏好：下载源与关闭窗口行为；这两个字段目前同属一个 UI 偏好 CAS 组，不拆成两个独立全量提交表单
- 运行：全局加载默认、空闲策略、文件校验超时，明确需要停服及生效时间
- 请求默认值：仅影响后续请求，独立保存

低频全量扫描折叠到“高级维护”，展开后说明只处理何种来源与范围。常规列表没有扫描按钮。对默认目录“缺失/不可读”保留异常摘要，但不能因此把其他已登记外部模型一概判为不可用。

每组只保存自己的字段；保存后保留真实回执。组标题显示“未保存”“需停服”“版本冲突”等必要状态，即使内容折叠也能定位问题。不要把保存和重新加载合成一个无说明的全局按钮。

配置迁移、CAS 冲突、草稿恢复是异常/恢复流程，不是常驻说明段落。触发时不得收起到用户看不见；冲突仍需比较并明确选择，不能自动采用新 revision 重发旧草稿。

### 3.7 活动与辅助聊天

活动默认先显示当前任务，再显示精简历史行。行内任务名、实际终态、时间；展开看到阶段、受控错误、诊断码与可用恢复。历史清理继续确认，并保留尚在途/待确认任务。

辅助聊天保持简单：驻留模型标识、实际请求参数的二级入口、消息区和输入区。聊天返回原入口，不返回不可预测的页面。中文输入法 Enter 不触发发送，Shift+Enter 换行。已有中断输出不自动重发。

## 4. 全局任务与异常呈现

任务属于 controller，不属于页面。布局可以收起，但不能因此结束、取消、失去真实终态或创建第二项任务。

首层用一条任务摘要：任务名称 → 真实阶段/进度 → 查看详情 → 已支持的取消/重新确认。模型加载无独立取消能力时不能制造取消按钮。下载未知总大小不编造百分比或剩余时间。

- 发起页可展开完整进度；切到其他页面默认紧凑呈现，防止完整结果卡将设置/API 推出首屏
- 活动页始终能找到同一任务的结果；“查看阶段结果”恢复原结果，不重放任务
- 在途只有“收起详情”，不能用“关闭”暗示已取消；取消后显示“正在取消，等待终态”
- 终态可以关闭首层摘要，活动保留；部分添加/已下载但登记失败保留部分成功事实
- 结果待确认/持久化未确认不可显示为已回滚、可安全重做；主动作是核对实际状态
- 当前阻断错误不能只出现在折叠区，首层至少展示原因与下一步；重复解释只保留一处
- 关闭旧结果不得清除新文件选择或新任务；重复点击只产生一次原生命令

## 5. 焦点、返回与可访问性

1. 页面切换后将焦点移到该页可聚焦标题/主区；二级详情返回后恢复触发按钮，并尽量恢复列表位置。异步轮询不重置页面滚动。
2. 保留 Alt+1…5；不与中文输入法组合或字段输入冲突。若沿用快捷键导航即取消未确认弹窗的既有行为，必须只取消草稿确认，不能触发确认动作或中断已确认任务。
3. 弹窗打开时焦点进入安全的“取消”；Tab/Shift+Tab 在有效控件内循环，Escape 取消；关闭后恢复触发点，触发点已卸载则落到目标页标题。
4. 弹窗焦点管理不能随 onCancel 回调对象或后台快照变化重新初始化。轮询发生时，已聚焦的确认按钮必须仍保持焦点。
5. 原生 details/summary 优先于手写展开控件；自定义控件提供 aria-expanded、aria-controls、可访问名称与键盘激活。
6. 焦点轮廓明显且不被固定栏/overflow 裁剪；选择、错误与通过不只靠颜色。正文目标对比度至少 4.5:1，关键大字与控件边界按适用标准另验。
7. role=status/aria-live 只播报有意义的阶段变化，不在每次毫秒计时或无变化轮询重读整页；严重且新出现的阻断错误使用 alert。
8. 尊重 reduced-motion；取消旋转动画后仍保留文字状态。原生高对比度、150%/200% 缩放、键盘顺序与读屏需在 Windows 独立实测。

## 6. 流程模拟与验收矩阵

模拟使用 React/jsdom 与受控原生接口 mock，覆盖 DOM、动作次数和状态语义，不覆盖真实文件选择器、剪贴板、视觉像素、鼠标命中或 Windows 窗口。

| 流程 | 必须保持的结果 | 本轮首轮依据 |
| --- | --- | --- |
| 首次打开/空库 | 不自动启动/扫描；提供模型入口与离线初始化 | App、journeyCorrections、Configuration |
| 下载→设置→返回 | 保持下载上下文和筛选；保存前不换源 | 新观察 B02 复现旧版丢失，交前端修复 |
| 单/多文件添加 | 只登记选中；批量不自动测试；停服后再确认 | ModelAdd |
| 添加部分成功 | 每文件结果保留，关闭/恢复不误删新选择 | ModelAdd、WorkflowTasks |
| 加载/切换 | 单次原生命令；不手动重复 unload；不抢占 | journeyCorrections、Configuration |
| selected 但已卸载 | 不显示当前驻留、有效参数或可调用 ID | journeyCorrections、ReviewRegressions |
| API 密钥复制 | 取消不复制，确认走原生，无秘密 DOM | App、Configuration |
| 弹窗期间快照刷新 | 当前键盘焦点保持 | 新观察 B01 复现旧版焦点被抢回，交前端修复 |
| 配置草稿离页/重开 | 分模型保留；明确恢复；冲突不自动覆盖 | Configuration、UnsavedDrafts |
| 失败/断连/取消 | 不重放，不抢停止，不假终态；可核对 | ServiceControl、ReviewRegressions、WorkflowTasks |
| 重复动作 | start/add/load/copy/chat 不重复执行 | 上述对应交互与 controller 回归 |

首轮证据：基线 `a14eb6fdb1858baf507c8b9a8509b0ca30df1316` 的前端副本，独立目录运行 10 文件 / 152 项通过，其中 150 项为现有流程回归，2 项为“旧问题确实存在”的观察断言。观察通过不是缺陷修复完成。

## 7. 实施与复核优先级
