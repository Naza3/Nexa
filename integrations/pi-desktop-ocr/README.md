# Nexa OCR — PI Desktop 插件

独立图片 OCR 工作台：Nexa 只负责本机模型与推理，PI Desktop 提供选图、按导入顺序批量识别、Markdown、正文下性能摘要、最近100条非空结果以及 TOML 设置记忆。

## 安装和首次连接

1. 使用 **PI Desktop 0.17.0 或更新版本**。本插件依据0.17.0源码契约制作；更新版仍需按实际兼容性验证。
2. PI Desktop 左侧栏底部 **扩展**（插头图标）→ 右上角 **更多操作**（三点图标）→ **安装插件包**，选择 `io.github.naza3.nexa-ocr-0.1.0.piplug`。若宿主显示权限提示，核对后允许；也可以在扩展详情查看本机网络、剪贴板和目录权限。
3. 在右侧工作面板选择“图片识别”，或在命令搜索中运行 **Nexa OCR：打开图片识别**。
4. 启动 Nexa 的运行服务。首次先在 Nexa 登记 GLM-OCR 主模型和配套 mmproj；插件不下载、导入或修改模型文件。
5. 在插件“连接 Nexa”中填写 Nexa 实际地址，默认 `http://127.0.0.1:18080`。
6. 点击“选择令牌文件”，在Windows文件窗口地址栏输入 `%LOCALAPPDATA%\Nexa\secrets`，选择 `api-token`。也可以手动粘贴令牌；使用自定义Nexa数据目录时选择其 `secrets/api-token`。这是本机令牌，不是可选局域网令牌。不要把令牌发送给他人。
7. 点击“连接”。模型下拉框只显示已登记的配对视觉模型。选择目标 GLM-OCR 后导入图片，点击“开始识别”。

插件在本机连接上验证Nexa的HMAC服务身份后才发送认证令牌；仅允许 `127.0.0.1`，不使用远程服务，也不启用CORS。两程序必须运行在同一电脑。Nexa若重启，点击连接刷新实例后再识别。

## 使用

- 多选、拖入或分次导入PNG/JPEG，一次最多20张，保留浏览器传入的文件顺序；不按文件名重新排序。开始前可以上下移动或移除。
- 最终发送图片每张≤4MiB、单边≤8192、总像素≤16,777,216；默认保留原图。需要时显式选择发送最长边，PNG缩放保留无损编码；缩放后的大小和尺寸仍严格检查。
- 默认提示词 `Text Recognition:`，输出上限4096（当前Nexa最大值）。图片、提示词和输出共同占用上下文；模型上下文/线程/批次在Nexa模型参数档案中配置。
- “自动加载”开启时，空闲Nexa按需加载或切换所选模型。已有其他运行或排队任务时暂停提示，不抢占。故障状态不自动恢复。关闭此开关只用当前已加载的同一模型。
- 停止只取消本插件的当前请求/加载，保留已生成文字。停止、失败、token截断或保存失败后暂停整批；再次开始只执行尚未开始的图片，不自动重试失败图片。需要重新识别某张图时明确重新导入。
- 插件等待超时默认1800秒，可改30–86400秒；Nexa自身“推理执行超时”是独立设置。若后端300秒先超时，仅增加插件等待时间无法延长后端预算。
- Prefill/decode速度和耗时来自同一次Nexa请求的真实指标。总耗时包含插件准备/加载/网络，不能当作引擎生成耗时；取消/失败缺指标时显示不可用。
- 复制只复制Markdown正文。另存时选择目录，生成新名称 `.md` 文件；原始HTML、远程图片及主动链接不会在预览执行。

## 数据和退出

插件私有数据目录由 PI Desktop 提供。`preferences.toml`保存模型选择、地址、提示词、输出预算、等待时间、缩放和视图；`history.toml`保存最多100条非空结果（总上限16MiB，超限先删除最旧记录）。不保存原图或待运行队列。运行中的部分文字约每4秒检查点保存，异常退出仍可能丢失最后几秒内容。

令牌默认仅在插件进程内存中。显式勾选“记住令牌”才保存到私有 `credentials.toml`，文件按当前用户权限创建；没有额外加密，不等同系统凭据保险箱。取消勾选/清除令牌会删除该文件。插件不会后台扫描Nexa凭据目录。

关闭插件面板后任务仍在插件进程运行，再打开可恢复查看；禁用插件或退出PI时取消当前任务并尽力保存部分内容，未开始队列不恢复。Nexa原生清理可能晚于插件退出；其他客户端应继续遵守Nexa忙状态。

## 开发和打包

```sh
npm ci
npm test
npm run build
# 将下列变量设为已构建的 PI Desktop 官方 devkit CLI 绝对路径：
export PI_PLUGIN_DEVKIT_CLI=/path/to/PI-Desktop/packages/plugin-devkit/dist/cli.js
npm run check
npm run pack
```

Windows PowerShell使用 `$env:PI_PLUGIN_DEVKIT_CLI = 'C:\...\dist\cli.js'`。devkit是上游私有workspace包，按其插件开发指南从固定源码构建，不能直接npm安装同名公开包冒充。本环境已在 `/workspace/onboarding/pi-ocr/upstream-devkit/` 构建固定版本，脚本可直接找到。`build/plugin`为可加载的开发插件目录，`dist/*.piplug`为最终可安装包。产物包含依赖与许可，用户安装不需要Node、npm或再次编译。

流式网络和私有TOML文件由插件Node进程处理，因为宿主 `pi.net.fetch`只返回完整正文、不提供SSE或取消句柄；每次连接/开始前先通过宿主network权限检查，再在固定回环地址上使用带身份验证的Node HTTP，禁止重定向和自动重试。模型输出不进入PI Agent工具执行链。

实际测试范围、产物摘要和未验证条件见仓库验证记录；协议/浏览器模拟/官方子进程验证不等同Windows Electron完整安装与用户i5设备运行。
